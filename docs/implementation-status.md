## Decisions Made
- Source-specific DTOs remain confined to their Claude and Codex source directories; shared domain, app shell, persistence, and UI surfaces consume only the source-neutral parser/projection contract.
- One decoded benchmark envelope projects benchmark and embedded source-status segments independently. Community parsing remains separate and cannot feed benchmark quality or Pareto inputs.
- Upstream model keys are preferred. Name fallback only trims, lowercases, collapses whitespace to hyphens, and removes nonsemantic edge punctuation; version, date, thinking, context, and sizing suffixes remain identity-significant.
- Missing upstream benchmark name/version, token fields, agent steps, and nullable measurements remain `nil`; percentages stay in the recorded 0...100 source unit and are not double-scaled.
- Community average is not a percentage. The public homepage and current response establish an inclusive 1...10 scale; domain ratings carry scale minimum `1` and maximum `10`, while a missing average remains `nil`.
- A present `latest_label` first matches `labels` exactly. If the source independently localizes that label, `latest_at` may derive the required aligned `M.dam`/`M.dpm` label using its declared timezone offset; failure to resolve an aligned point still rejects the benchmark. Only an absent `latest_label` selects the final aligned source point. Missing/null quota returns a source-status `.decoding` failure while leaving a valid benchmark available.
- Invalid optional dates become `nil`; empty models, misaligned arrays, negatives, percentages outside 0...100, passed greater than valid, duplicates in quota identities, and explicit source caps reject their segment.
- Snapshot dedupe keys are `sourceID|datasetType|contentFingerprint`; each table also carries `sourceID`, `seriesRevision`, `sourceUpdatedAt`, `fetchedAt`, and a single encoded immutable domain dataset.
- Canonical fingerprints sort JSON keys and order semantically unordered model/rating/quota collections by stable ID. `fetchedAt`, request duration, response headers, and local errors never enter the hash.
- LKG queries scan newest `fetchedAt` first, verify decoded content against the entity fingerprint/source/revision, report corruption, and continue to the preceding valid snapshot.
- Duplicate-valid and not-modified attempts update lightweight metadata without adding a trend point. Segment failures update only that segment's metadata and preserve all LKG snapshots.
- Raw retention is enforced after every write. Failures exactly 30 days old remain eligible; failures one millisecond older are removed. The injected data-root parent is resolved as the trusted anchor, every existing store-path component is checked without following links, sample reads use `O_NOFOLLOW`, and physical cleanup removes symlinked, malformed, and hash-mismatched entries.
- Benchmark and source-status protocol calls share one cached acquisition per synchronization session; quota is never fetched separately. Community remains a second independent request and cannot invalidate the shared envelope.
- Manual refresh joins an active task, bypasses elapsed backoff only, and never bypasses persisted Retry-After. Periodic backoff follows 1m/5m/15m/30m/2h/6h; network/wake recovery requires stale data and the 60-second attempt interval.
- A 304 updates attempted/success timestamps and validators without inserting history. Any valid or 304 segment clears elapsed backoff; failed new payloads only update that segment's error metadata and never replace LKG.
